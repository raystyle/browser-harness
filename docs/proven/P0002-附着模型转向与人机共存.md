# 附着模型转向与人机共存

- 状态：已完成（封存）
- 日期：2026-09-10（回溯归档；方案主体 2026-09-05 落地，D27 容错 2026-09-08 补齐）
- 关联：PRD D11/D27；研究 S001；踩坑 M101（M006 Edge 兜底）；diary 2026-09-05/09-07/09-08

## 背景与问题

移植初期沿袭 Python 主仓的 agent 专属 Chrome 形态：程序自己 spawn 一个带调试端口的浏览器实例（继承老栈登录态），任务级隔离、独立锁管理。问题三重：

1. agent 拥有的浏览器与用户自己日常使用的浏览器是两套世界，登录态、扩展、习惯全部割裂
2. spawn 家族（agentChrome/taskIsolation/locks 三模块 + `bh chrome` 与 chrome-mode）是移植仓里最重也最脆的部分，Windows 分离进程生命周期问题不断
3. Chrome 136 起默认 profile 拒绝开远程调试端口，老通道正在被上游逐步封死

用户裁定架构转向：共存不扰人。agent 不该拥有浏览器，该附着用户自己打开的浏览器。

## 目标与非目标

目标：

1. 只附着用户自己打开的浏览器，永不 spawn、永不重塑窗口、绝不关用户 tab
2. 专属 tab 铁律：agent 的工作在自开专属 tab 上，与人类浏览互不干扰
3. x-monitor 等常驻应用随之改造，在用户浏览器上安静收割

非目标：

- 不做「agent Chrome + 附着」双模式并存（彻底移除，不留开关）
- 不做窗口前台化/恢复等任何 reshape 行为（即便为对抗后台节流）

## 方案

- **生死门先行（S001）**：Chrome 144+ 官方 auto-connect 通道（chrome://inspect/#remote-debugging 手动开启）+ DevToolsActivePort 文件发现（该版本起 HTTP /json 端点不服务，注册表扫描不可用）。PoC 证伪则整体方案告警退出，无兜底
- **发现与排除**：扫描各 Chrome 变体（Stable/Beta/Dev/Canary）的 DevToolsActivePort 文件；Edge 永不发现（M006：早期静默兜底 Edge 的教训机制化）
- **守护进程附着语义**：daemon 首次使用时幂等拉起并附着；陈旧 session 自愈；端口表强杀三级关停（stop 原语）
- **专属 tab 铁律程序化**：守卫在 Session 调用层，`session.domains.Browser.close()` 也被拦；只关自己开的 tab
- **x-monitor 共存改造**：收割面只认 x.com 根/home 时间线（HOME_URL_RE）；用户浏览非时间线页时静默等待不动用户页面（D27 双闸门：waitForTrigger 与 round 都过 homeTab 判定）；无任何 x.com tab 时仍后台自建 home（D40 已改：只附着用户已打开的时间线，缺 tab 持续等待，永不自建；探针/收割 eval 按 targetId 钉死不抢活动 tab）
- **窗口操作清零**：foreground/restoreWindow（dock 尺寸 + activate + minimize）等对抗后台节流的手段整体移除，运行时零 `Browser.setWindowBounds`/activate 调用点

## 备选方案

- 保留双模式（agent Chrome 可选）：否决，双模式意味着两套锁、两套生命周期、双倍维护面，且忠实移植原则在本需求让位是用户明示裁定
- 自动为默认 profile 开调试端口：否决，Chrome 安全策略已封死，自动化空间不存在
- 远程调试协议替代通道（CDP over extension 等）：未采纳，官方 auto-connect 已满足，引入扩展面徒增复杂度

## 风险与回滚

- 风险：Chrome 版本策略再变（auto-connect 通道收窄）；后台 tab 节流影响收割节奏；用户浏览器多实例端口语义
- 回滚：git 历史保留 spawn 家族最后版本，可回退；实际从未需要

## 实施过程与经验

- S001 生死门一次通过，但发现通道细节与社区通行认知差异大（/json 端点不服务、注册表扫描失效），这类「上游正在收紧」的通道必须以官方文档 + 实机双确认
- M006 教训前置生效：发现逻辑写死排除 Edge，宁可漏发现不可错附着
- D11 硬规则「零 reshape」源于早期对抗后台节流的窗口操纵：附着用户浏览器后这类操作全部越界，节流问题改由「js() 对隐藏 tab 仍可求值」的特性吸收（只有绘制节流，无求值节流）
- D27 是共存的补完：用户浏览期间应用报错刷屏本身就是扰人，「等待而非报错」是人机共存的第二半
- 最有价值经验：**忠实移植原则可以有明示让位先例**。D11 是首个整块偏离 Python 主仓的架构决策，让位依据（共存不扰人）与范围（仅此一处）都写进 PRD，后续需求不援引泛化
