# G001：文档标准细则

> 本仓文档的命名、结构与事实标记标准（精简起步版，按需扩充）。

## 命名

- 文件名即标题；编号目录文件名以编号开头（PNNNN/SNNN/RNNN/GNNN-短名.md）
- 不含空格、括号、冒号；research/diary 用 `-` 断句的博客式长标题

## 结构

- 标题干净（不带括号/口号/破折号），解释放标题下一行 `>` 引用
- 树形分层；h2 = 一节一事；命令进代码块；关键事实用表格

## 六态标记

事实性断言必标：`[实证: ...]` / `[推断: ...]` / `[经验: ...]` / `[记忆: ...]` / `[假设: ...]` / `[直觉: ...]`。关键结论必标；禁止把没验证写成已验证。五态为进入实证服务：`[假设]`/`[推断]` 写清验证动作、`[记忆]` 附复核点；悬空中转态收尾必处置（升实证、留 research 或注销）。

## 路径写法（全仓统一）

- 本仓是跨平台协作仓（npm 三平台分发），文档路径一律**正斜杠** `docs/proven/P0001-xxx.md`；禁止与反斜杠混用
- 命令示例跟目标平台 shell；跨平台示例用正斜杠 + 标注（依据 env-platform.md 第三节）

## 登记与门禁

- 新文档建成登记 INDEX 对应节
- md 禁字四类（破折号/连接号、Unicode 箭头、emoji、智能引号与全角字母数字）为 error 级，代码块/行内代码/链接豁免；箭头写 `->`，破折号改写为冒号或逗号
- 本仓已接 project-evo md-guard（PostToolUse 挡板）与 check.py（PE-01~13）；提交前跑 `python <skill>/scripts/check.py` 全绿
