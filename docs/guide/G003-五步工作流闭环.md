# 五步工作流闭环

- 状态：现行（Guide，规范与禁令）
- 日期：2026-09-10（依 project-evo flow-workflow 本仓化）
- 关联：AGENTS 工作节奏第 4 条；验证门禁 R001；经验沉淀 G004

## 一、五步总览

发现任何问题（文档滞后、代码缺陷、规则缺失、行为异常）时的标准处置路径，一步不跳：

| 步 | 动作 | 要求 | 禁止 |
| --- | --- | --- | --- |
| 1 定位 | 先搜后动 | `rg` 四步（INDEX 至 文件名 至 全文 至 mistakes）找到既有规则/先例/坑位 | 跳过检索直接改、重复造已有规则 |
| 2 归类 | 判断问题性质 | 五去处择一：错修文档（内容不实）、缺补规则（无章可循）、知识落 research（机理待研究）、出错记 mistakes（踩坑当场）、实证进 references（做法已验证） | 只修表象不归类、一处问题改一半 |
| 3 修正 | 改在源头 | 权威源文件先改，下游引用同步；一条知识只有一个权威落位 | 改下游留源头、双份并行埋漂移 |
| 4 验证 | 跑机器门禁 | `npm test` 全绿（含 typecheck:apps）；文档改动跑 evo scan 禁字；结构变更跑断链检查 | 修完不验证、只信肉眼 |
| 5 提交 | 一事一提交 | feat/fix/docs/chore/test 前缀 + 中文描述；提交后 diary 记钩子 | 一笔混多事、提交不留痕 |

## 二、与四原语的衔接

- 五步的「归类」决定改动落位；落位后按 AGENTS 文档义务表对齐（登记 INDEX、同步索引节）
- 目标级的工作走四原语（PRD 登记、GOAL 立项、PLAN 计划、TODO 进度）；五步闭环是目标内与目标外的**问题处置**路径，两者并行不悖
- 执行中发现偏离：就地纠偏后回写 PLAN/TODO，不让偏差只留在对话里

## 三、知行合一纪律（底层依据）

- **知落行**：规则写进 guide 后必须落到机器约束（hook、测试门禁、CI），只写文档的规则会被再犯
- **行返知**：每次踩坑与修复回写 mistakes（现象 + 根因 + 正确处理），同型二犯升格 references 工作流（细则 G004）
- 本仓现有机器约束实例：md-guard 禁字 hook（PostToolUse）、`npm test` 前置 typecheck:apps、CI 三平台矩阵、`bh skill sync` 三线哈希防漂移

## 四、验收清单

1. 问题处置后能回答「落位在哪、依据什么规则、谁同步了下游」三问
2. 修正过的文件对应门禁全绿（test / scan / 断链）
3. 新增规则或文档已登记 INDEX 并挂进意图路由（未登记等于不存在）
