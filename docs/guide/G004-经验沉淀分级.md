# 经验沉淀分级

- 状态：现行（Guide，规范与禁令）
- 日期：2026-09-10（依 project-evo exp-sedimentation 本仓化）
- 关联：AGENTS 工作节奏第 6 条；五步闭环 G003；六态 G001

## 一、两级分类总表

| 类 | 定义 | 落位 | 检索路径 | 产生时机 |
| --- | --- | --- | --- | --- |
| 成功经验（plan） | 做相同的事可参考的方案与过程 | `docs/proven/`（P 编号） | INDEX 方案表 | plan 验收成功后归档 |
| 成功经验（工作流） | 做什么就按什么流程来的正确工作流 | `docs/references/`（R 编号） | 意图路由（AGENTS）+ INDEX | 研究收尾 `[实证]` 后沉淀；mistakes 同型坑二犯后抽升 |
| 错误经验 | 出错后的纠偏与处理方法 | `docs/mistakes/`（M 编号） | AGENTS 踩坑条目 + INDEX 错误速查 | 踩坑当场（禁止收尾补） |

## 二、成功经验链

- **proven**：plan 验收成功后归档（背景、取舍、实施过程、经验节，模板 `docs/guide/template.md`）；下次做同类型的事先搜 proven 找先例
- **references 时机一（研究实证后）**：研究收尾结论六态定级，`[实证]` 的做法沉淀进 references，下次直接用；`[推断]`/`[假设]` 禁止跳级
- **references 时机二（二犯升格）**：mistakes 同型坑二犯以上，纠偏方法抽升成正确工作流进 references；错误条目保留现象与根因，指向新位置

## 三、错误经验链

- **当场规则（强约束）**：踩坑当场在对应 M1xx 分类文件接编一行（`| 编号 | 错误现象 | 根因 | 正确处理 | 首次踩 |`），同根因同型合并；禁止「先留着收尾再说」
- 主题需深挖机理时落 research（mistakes 记现象级条目，research 记机理，两处互指）
- **集成约束（二犯以上必配）**：只写文档的纠偏会被再犯；同型坑二犯起必须落至少一条机器可执行约束，四形态：
  1. agent hook（本仓实例：md-guard 禁字 PostToolUse 挡板）
  2. 测试门禁（实例：`npm test` 前置 typecheck:apps 纳管 apps 层）
  3. git 提交钩子 / CI 常驻（实例：三平台矩阵）
  4. 运行时自检（实例：`bh skill sync` 三线哈希、`bh doctor` 资产一致性）
- 规则是知，约束是行；只有文档没有约束的纠偏是知行分离，必再犯

## 四、边界与互转

- 一条知识只有一个权威落位：proven 管成功 plan 过程；references 管实证做法与工作流；mistakes 管错了怎么纠；research 管为什么与待验证
- 同一事件可两处各留一行但内容不重复（mistakes 记纠偏，references 记工作流）
- 实证与经验循环复利：实证多次重现固化为经验，经验指导下一次实证；悬空中转态（推断/假设）收尾必处置（升实证、留 research 或注销）

## 五、验收清单

1. 新 references 文件有意图路由或 INDEX 指向（能被检索到）
2. 新 mistakes 条目有根因与正确处理两列（不是只记现象）
3. 研究收尾时 `[实证]` 结论在 references 有落位（或明确说明无需沉淀的理由）
4. 同型坑二犯后 mistakes 条目已升格或指向 references 工作流
5. 二犯以上的错误已配集成约束（四形态至少一条落地）
