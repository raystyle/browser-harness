## 主线：看板事件混排疑云与页面诊断

1. **用户疑「x-intel::x-monitor 事件为何有 hs.d3fend.cn」**：三源混排拆解定案。「新贴 N 个」出自 worker.mjs 的 wlog 流水（收割面 HOME_URL_RE 只认 x.com 根/home，BH_ATTACH_URL_MATCH=x.com，代码层不可能碰别站）；「页面空白 + URL」是 page-detect watch 的告警（常驻探测附着浏览器全部 http(s) 页面，D18），昨天 19:28 首报后驻留看板通知区，与 12:58:43 的收割流水同屏渲染造成「x-monitor 在监控该站」的错觉。今天盘面无新 d3fend 告警（page-watch.log 今日无巡检记录，app-runs 只有自查两条）。
2. **hs.d3fend.cn 空白根因**：原子复现（单次 eval 内开 tab + 导航 + 等 8s + 双采 HTML 与存活态）拿到铁证：126 字符空壳文档（title 为马 emoji、空 body、零 script、readyState complete、tab 稳定存活）。非 CF 墙（challengePlatform false）、非加载慢、非渲染挂起，是服务端（网关或源站）在吐空文档，至少自 09-08 19:28 起如此。page-detect 七判复验 verdict=blank，告警准确。
3. **agent 诊断面踩坑两条**：(a) 两次独立 bh eval 之间活动 target 会被 x-monitor 抢走（其 waitForTrigger 每 6-8s switch_tab 回 x.com/home），第二次读 outerHTML 读到 548KB 的 X DOM（draftjs 特征）险些误判页面有内容；诊断类片段必须单 eval 原子完成或显式钉 target。(b) 首次开的 tab 在下一次寻址时已消失（No target with given id），同法复现未再出现，存疑挂账不深挖。

## D38 x-monitor 收割风暴限流接线（0.6.4）

- 根因双叠加：`MIN_ROUND_SPACING`（X_MIN_SPACING，默认 60s）自声明起从未接入主循环（`lastRoundAt` 只写不读）；触发探针 PILL_COUNT 查不到 pillLabel 时走 tab 标题 `(N)` 徽标路径，后台 tab 未读计数永不清零，触发常燃。实机 8-13s 一轮空转收割（x_worker.log 连续「新贴 6 · 已存在 6」，看板被刷屏）。
- 修复：主循环 waitForTrigger 返回后、jitter 前置限流闸，距上轮不足 60s 则带心跳等待补差额（supervisor 存活视角不变）。触发语义与收割面零变化。
- 部署链（D27 同款路数）：pack 0.6.4 至 install -g 至 skill sync（+worker.mjs）至 `bh upgrade --offline --yes` 滚动对版（终验全守护 0.6.4、看板 200）至 x-intel stop/start。dist 未动（纯 assets 修复），daemon 滚动只为版本号对齐消除漂移提示。
- 验收：npm test 82 全绿（build + typecheck:apps）；实机轮间隔 8-13s 变 69-74s（60s 闸 + 6-8s 探测周期 + 10s 内 jitter 的预期值），首轮不限流属设计（lastRoundAt 初值 0）。
- 方法论：常量「声明未接线」类 bug 的检出信号是日志节奏与设计文档不符；诊断入口先数日志时间戳分布，再看代码里该常量的读写引用是否闭环。
