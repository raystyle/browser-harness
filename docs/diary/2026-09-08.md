## D30 bh upgrade 升级轮换（0.4.1）

- 用户诉求演进三轮：升级程序检测老守护稳定轮换 -> 新程序初始运行检测 -> 默认 GitHub Release 也支持离线。裁定：检测自动+轮换显式；包源三态（Release 默认不降级 / --from 显式源 / --offline 只滚动本地）。
- 实现：daemonVersionDrift（health.version 缺字段视为 pre-0.4.0）+ 启动一行提示；upgrade 五步滚动 spawn 子进程复用既有 stop/start 语义；--from 的安装在后台引导进程做（本进程退出后 npm install -g，规避 Windows 运行中 dist 文件锁，装完自动 bh upgrade --yes --offline 续跑）；upgradePlan 纯函数 4 单测。
- 实机验收即封版流程本身：装 0.4.1 后守护面全 0.4.0，`bh upgrade --yes` 五步全绿终验对版。滚动过程子进程的漂移提示穿插可见（提示机制实战）。
- **Commander 选项三连环（实机验收逐一抓出）**：(1) 新命令未注册 KNOWN_COMMANDS 被 legacy 裸片段路径吞给 daemon eval（ReferenceError: upgrade）；(2) 无参命令 action 第一参是 opts 对象而非命令对象（cmd.opts 报错；统一改闭包 xxxCmd.opts()）；(3) 顶层 -y/-n 定义会抢占子命令同名 flag（最小复现实锤，enablePositionalOptions 解决：子命令前归顶层、后归子命令）；program 级操作数必须从 program.args 取。教训：选项解析类改动必须逐命令带 flag 实测，dry-run 与 --yes 两条路径都要走一遍。
