## D05：锁与浏览器互斥重构（晚间）

用户判词「程序仍然很乱」，指定学习 nu_plugin_browse 的锁与浏览器互斥。通读其 session.rs / launch.rs / browse_open.rs，方法本质三条：fs4 内核级排他锁（崩溃自动释放、竞争者阻塞）、锁包住「检查到关停到启动到落状态」全序列、`.session` 状态文件自证归属 + 优雅/端口表强杀两级关停。

对照诊断出 bh 三个乱源：30s stealAfterMs 偷活锁（task-port 自己用 1h 证明作者知道不对）、isAgentChromeRunning 只 ping 端口（M006 根因层）、强杀无端口表兜底。零依赖内落地：

- 锁：`stealAfterMs: Infinity` 只认 pid 死亡（无内核锁时时间维抢占天然不安全），锁文件加 meta
- 归属：launchAgentChrome 锁内写 bh-agent.json（bin/port/pid），运行判定升级为端口活 + 归属一致 + UA 家族匹配
- 关停：第三级端口表强杀（netstat/lsof -> kill -9）

验证：并发双 start 端口表 LISTENING=1（单实例）；Chrome stop/start 后 daemon 不重启 22s 自愈重附着（此前误判为缺陷，实为 15s 限频时序）。M007 归档。

## D08：sessions 状态探测原语（午夜前）

用户三连需求收敛成一个原语：`bh sessions` 看实例/进程/tab 表/附着策略，外加 `bh --new-tab`。中途用户纠偏一次：「字典也许不专业，看代码是怎么定义的对象模型」。说得对，第一版我拍了个六层概念字典，重做成从代码提炼：instance（paths.ts 注册表）、browser（进程树+归属记录）、session（一条 flatten WS + activeSessionId 自动注入，路由唯一机制）、tab（switch/activate/new/close 四原语）、placeholder（_is_agent_startup_placeholder 的占位页判定）、window（有 windowId 无操作原语，不是一等对象，如实写明）、navigation（goto_url=地址栏等价）。

附着策略四入口显式化：eval=attach 活动 tab、app=host 复用、--new-tab=explicit、--once/--batch=isolated。首用即见效：输出暴露 2 个僵尸实例注册（foo/x-monitor，daemon 死了注册残留）和 4 个残留 about:blank，当场清理。--new-tab 踩了 postEval 进程即退的坑（每 CLI 调用只能一次 eval），改单段复合代码。

## D09：rmux 探测原语

用户指出「rmux 没有会话和 pane 之类的 list 原语」。核实：rmux.ts 内部有 listSessions/listPanes（x-monitor 自用）但粒度粗且零暴露。补齐：panes() 结构化清单（tmux format 变量：session/window/pane/title/command/path，竖线分隔）、daemonAlive()（list-sessions exit 0 判定）、status() 聚合，CLI 暴露为 `bh rmux`。空态如实报 daemon:false；起测试会话验证满态（target `bh-test:0.0`、path、command 全字段）后清理。与 bh sessions 对偶：浏览器面 + 监督面两条探测原语齐了。

小教训：构造含 `\x1f` 分隔符的代码经工具写入时转义被解释成真实控制字符进文件，Edit 无法匹配——换回久经验证的竖线分隔并用行级替换修复。构造含转义序列的源码时用可见字符做分隔符。
