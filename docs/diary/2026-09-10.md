## D40 x-intel 监控与搜索分道（监控只附着，搜索自开 tab）

- 用户指令：「x-intel 这个应用的监控和搜索功能没有分开独立，监控应该是自己轮询扫描有没有打开的 x.com 主页去附着，没有就继续等。x-intel 的搜索应该是自己新打开 tab 页去搜」。读代码核实两处越界：worker 在无任何 x.com tab 时 `h.new_tab('https://x.com/home')` 自建时间线 tab（用户浏览器被应用塑形）；harvest 又 `tabs.find(t => t.url.includes('/search'))` 抓**任意** `/search` tab 直接 `goto_url`（用户自己的搜索页被劫走）。两件事共享一套 tab 心智，正是「没分开独立」。
- 监控改造（worker.mjs）：删自建分支，`round()` 无 home tab 直接返回 null = 等待；`waitForTrigger` 缺 tab 超 `X_NO_HOME_REPORT_MS`（默认 15s，一档抖动即报）返回 `no-home-tab`，主循环写 running 等待态（文案区分「无 x.com tab」与「用户浏览其他 x.com 页面」），日志只在状态切换时打一行（等待是状态不是事件）。探针与收割 eval 全部改 `js(expr, targetId)` 钉死（新增 `waitReadyPinned`），彻底去掉监控侧的 `switch_tab`：不再抢 daemon 活动 tab，与搜索分片各跑各的。
- 搜索改造（harvest.mjs）：`openOwnTab()` 用**无参** `new_tab()` 必建全新 target（关键：带 url 的 `new_tab` 会复用空白页，那可能是用户刚开的空 tab，会被劫持后又被关掉），再 `goto_url` 搜索页；跨分片复用同一个 tid；`finally` 里 `closeOwnTab()` 关掉自己的 tab（URL 已非 x.com/search = 用户接管，保留不动）。分片体抽成 `harvestSlice()` 让 try/finally 干净。
- 验收走**引擎隔离实验**（首次把 `bh headless` 用于常驻应用验收，方法落 R001）：起隔离引擎；①无 x.com tab 跑 worker：日志「等待打开 x.com 主页 tab（只附着，不自建）」且 tab 数恒 1（旧的会自建，这条即回归判据）；②引擎导航到 x.com/home 再跑 worker：附着该 tab 探测并跑满一轮兜底收割，tab 数仍 1；③跑 harvest 单分片：运行中 tabs=2（原 tab + 自开搜索 tab），退出后 tabs=1 且 stderr「搜索 tab 已关闭」。82 测 + typecheck:apps 全绿。
- 踩坑 M019：组件文件（`assets/apps/x-intel/harvest.mjs` 这类只导出 main 的）直接 `node` 跑**静默 exit 0**，首跑验收假阴性；同族还有 `node dist/cli.js x-intel.mjs worker` 把文件名当 JS 片段求值。

## D41 第 2 轮修正：折叠按钮融进分界线（隐藏式）

- 用户修正：「折叠按钮应该是融入进列的分界上，是隐藏式按钮」。0.6.7 已发布的底栏方案作废，控制栏整体删掉。
- 落法：左右两条 1px 分界线各挂一个圆形箭头按钮（`.splitbtn`），基础 `opacity: 0` 完全隐藏，鼠标悬停分界线（`.split:hover`）或键盘聚焦（`.splitbtn:focus-visible`）才浮现；接缝的 `::after` 向两侧各撑 5px 扩大悬停/点击靶区但不加宽那 1px 线。收起的一侧把接缝变成 20px 槽位（= 按钮自身宽度，圆心落在 x=10 / 1430，**不被窗口边缘裁切**）并把按钮压到 .5 半透明，留一个看得见、点得回来的入口。

## D42 修复：瞬态探测 detach 误清附着面（看板误报已脱离）

- 现象：用户开着两个 x.com/home tab 时看板附着实例表 x-intel 显示已脱离。真机核实是假象：/meta connected:true 且 sessionId 活着、/tabs current:null；x_worker.log 收割轮照常跑（20:42 至 20:44 三轮新帖指示器触发）。
- 根因链：D40 后监控 eval 全部钉 targetId，`js(expr, tid)` 每次调用新开瞬态 session（attachToTarget、eval、detachFromTarget）；harness 用浏览器级 attach/detach 事件维护 tracked target，任何命中 tracked target 的 detach 都清空它（M018 机制）；监控探测的恰是 daemon 附着的 home tab，探测完一 detach 面就被清，只在下次探测的瞬态窗口被设回，看板每秒快照基本必然拍到空值。与第二个 home tab 无关，0.6.7 D40 起就会，用户开第二个 tab 时才注意到。
- 修法（harness.ts 一处语义）：区分持久 adoption 会话（attachFirstPage/switch_tab/set_session 汇入 adoptSession，记 adoptedSessionId）与瞬态探测会话（js 内部临时开）：有 adoption 时瞬态 attach 不改写、瞬态 detach 不清空追踪面，只有 adoption 自己的 teardown（tab 被关）才清；无 adoption 时（page-detect、懒实例首次页面级调用隐式 adoption 之前）行为不变；connect() 重连时三个指针（activeSession、attachedTarget、adoption）随 WS 一并清（eager 实例由 attachFirstPage 重建）。

## D44 x-intel 本地库分词搜索（wangfenjin/simple 二进制路线）

- 需求三轮收敛：用户先提「x-intel的搜索应该分词搜索」附 wangfenjin/simple 参考；第 1 轮我裁定 JS 分词（RMM + jieba 高频子集词典资产）并接线到 harvest 与 search 两入口；第 2 轮用户问「直接用二进制库？」，我评估 simple 是 SQLite FTS5 tokenizer 扩展（无独立 CLI、Node 调用需平台二进制）建议 JS 路线 + FTS 化另立项；第 3 轮用户裁定「我的需求就是本地SQLITE搜索用上这个库」，JS 方案全数回退（harvest 线恢复原样），走 FTS5 + simple 二进制。
- 生死门实测（先探后建）：node:sqlite 有 FTS5 且 `loadExtension` 可用（Node ≥22.13 allowExtension）；simple v0.7.1 Release 有 11 平台预编译；entry.cc 提供 `jieba_dict(path)` SQL 函数钉词典目录（默认 ./dict/ 是 CWD 相对，必须装载后先设）、`jieba_query()` 把查询串分词成 FTS5 布尔式；索引侧 tokenize='simple' 为 CJK 逐字 + 拼音并置（拼音检索是库自带能力）。
- 资产落位：`assets/bin/simple/{windows-x64/simple.dll, linux-x64/libsimple.so, osx-x64+osx-arm64/libsimple.dylib}`（Release v0.7.1，~4.2MB）+ 共享 `dict/`（取 linux zip 的 LF 版全量 jieba 词典，~11.2MB；pos_dict 不在 Jieba 构造参数内裁掉；idf 置空实测可跑但为保 snippet/关键词提取能力保留全量）。CI 矩阵（ubuntu/windows x64 + macos arm64 × node 22/24）平台全 vendored，测试不跳过。
- 核心接线：sqlite.ts `ensureSimpleFts`（loadExtension -> jieba_dict -> 外容 FTS5 虚表 `tweets_fts` content='tweets' -> 首建 rebuild；已存在则 COUNT 对账漂移自愈：降级期写入/手改库后下次搜索自动 rebuild）；`storeTweets` 显式维护索引（不用触发器：INSERT OR IGNORE 下触发器是否触发语义存疑，且 storeTweets 是唯一写入方，text 不可变）；`openDb` 带 allowExtension + 旧 Node 构造回退。search.mjs 关键词主路 `tweets_fts MATCH jieba_query(?)` JOIN 回 tweets，无二进制/加载失败回退 LIKE，信封加 `via: fts-simple|like|scan` 明示走了哪条路。
- 验收：6 条 FTS 单测（词序无关命中含「LIKE 真漏它」前置断言、存量 rebuild、索引后写入可搜、去重不重索引、缺二进制回退契约、平台二进制在位）；91 测全绿。安装态真库 2257 帖 `bh x-intel search 浏览器自动化` 出 `via: fts-simple` + 2 条命中（两条都是词序无关的 LIKE 盲区帖）[实证: 2026-09-10 安装态]。
- 顺带修 page-detect 报障（用户 21:55 看板消息「No target with given id found」）：tab 在 list_tabs 与 attach 之间被关是正常轮换，probeTab 捕获层对 -32602 静默跳过，不再当失败记事件（D27 哲学：轮换是状态不是错误）。
- 方法论：第三方「二进制库」接入先读它的扩展协议（tokenizer 注册名、SQL 函数面、词典路径解析），入口函数（entry.cc）比算法源码更能定集成契约；「vendored 原生产物 + 优雅降级 + via 字段明示」是零运行时依赖承诺下吃原生能力的标准形态（模式记 R002）。
- 验收：新增回归测试锁 pinned-eval 模式（同 target 瞬态探测不清、异页瞬态探测不劫持、adoption 自己的 detach 才清），83 测全绿；安装态 pack+install 后带 BH_ATTACH_URL_MATCH 重启 x-intel daemon：37 秒 10 采样 /tabs current 恒 4EA1AC8C，事件环同窗口 29 对瞬态 attach/detach 全落在被附着 tab（旧码每次 detach 都会清面）；四守护实态 default 待命、page-detect 待命、headless-engine 已停止、x-intel 已附着 [实证: 2026-09-10 安装态]。
- 验证中带出第二成因（未修，候选 D43）：spawnRepl 继承派生方 env，CLI/upgrade 重启的 x-intel daemon 丢 BH_ATTACH_URL_MATCH 变懒实例，eager 附着只在 worker 派生时发生（本轮裸 `bh --name x-intel --restart` 实测 sessionId:null）。附着偏好应实例化落注册表而非 env 继承，否则每次升级滚动后误报复现。
- 方法论：M018 的教训是「事件匹配键用稳定必填字段」，本轮补第二半：**事件维护的持久状态要分会话的持久性**。瞬态探针的 attach/detach 对称成对，拿它维护持久归属必然抖动；判别键应该是「谁有资格改状态」而不只是「事件长什么样」。
