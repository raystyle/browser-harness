## D40 x-intel 监控与搜索分道（监控只附着，搜索自开 tab）

- 用户指令：「x-intel 这个应用的监控和搜索功能没有分开独立，监控应该是自己轮询扫描有没有打开的 x.com 主页去附着，没有就继续等。x-intel 的搜索应该是自己新打开 tab 页去搜」。读代码核实两处越界：worker 在无任何 x.com tab 时 `h.new_tab('https://x.com/home')` 自建时间线 tab（用户浏览器被应用塑形）；harvest 又 `tabs.find(t => t.url.includes('/search'))` 抓**任意** `/search` tab 直接 `goto_url`（用户自己的搜索页被劫走）。两件事共享一套 tab 心智，正是「没分开独立」。
- 监控改造（worker.mjs）：删自建分支，`round()` 无 home tab 直接返回 null = 等待；`waitForTrigger` 缺 tab 超 `X_NO_HOME_REPORT_MS`（默认 15s，一档抖动即报）返回 `no-home-tab`，主循环写 running 等待态（文案区分「无 x.com tab」与「用户浏览其他 x.com 页面」），日志只在状态切换时打一行（等待是状态不是事件）。探针与收割 eval 全部改 `js(expr, targetId)` 钉死（新增 `waitReadyPinned`），彻底去掉监控侧的 `switch_tab`：不再抢 daemon 活动 tab，与搜索分片各跑各的。
- 搜索改造（harvest.mjs）：`openOwnTab()` 用**无参** `new_tab()` 必建全新 target（关键：带 url 的 `new_tab` 会复用空白页，那可能是用户刚开的空 tab，会被劫持后又被关掉），再 `goto_url` 搜索页；跨分片复用同一个 tid；`finally` 里 `closeOwnTab()` 关掉自己的 tab（URL 已非 x.com/search = 用户接管，保留不动）。分片体抽成 `harvestSlice()` 让 try/finally 干净。
- 验收走**引擎隔离实验**（首次把 `bh headless` 用于常驻应用验收，方法落 R001）：起隔离引擎；①无 x.com tab 跑 worker：日志「等待打开 x.com 主页 tab（只附着，不自建）」且 tab 数恒 1（旧的会自建，这条即回归判据）；②引擎导航到 x.com/home 再跑 worker：附着该 tab 探测并跑满一轮兜底收割，tab 数仍 1；③跑 harvest 单分片：运行中 tabs=2（原 tab + 自开搜索 tab），退出后 tabs=1 且 stderr「搜索 tab 已关闭」。82 测 + typecheck:apps 全绿。
- 踩坑 M019：组件文件（`assets/apps/x-intel/harvest.mjs` 这类只导出 main 的）直接 `node` 跑**静默 exit 0**，首跑验收假阴性；同族还有 `node dist/cli.js x-intel.mjs worker` 把文件名当 JS 片段求值。
