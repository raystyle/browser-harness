# S001：用户自开浏览器附着通道可行性

> D11 的生死门研究：用户自己打开的浏览器能否被 bh 稳定发现与附着。证伪则 D11 告警退出（PRD 裁定，无兜底形态）。状态：已完成（2026-09-05，判定可行）。

## 研究问题

| # | 问题 | 类型 |
| --- | --- | --- |
| Q1 | Chrome 136 及以后对默认 user-data-dir 禁用 --remote-debugging-port 的限制是否属实、影响范围（正式版/开发者通道、平台差异） | 外部事实 |
| Q2 | 用户自开浏览器暴露 CDP 的可用通道盘点：非默认 profile 启动参数、chrome://inspect 的 Allow remote debugging 许可流、--remote-debugging-pipe、其他 | 外部事实 + 实验 |
| Q3 | 发现机制：bh 如何发现用户浏览器（已知端口扫描、DevToolsActivePort 文件、用户配置声明） | 设计 + 实验 |
| Q4 | 一次性引导形态：bh setup-browser 装带调试口的快捷方式（Windows 注册表 StartMenuInternet、macOS/Linux 桌面项）的可行性与越权边界 | 设计 + 实验 |
| Q5 | 共存验证：附着后专属 tab 后台创建是否真正不抢焦点、不干扰用户正在看的页面 | 实验 |

## 已知线索（仓内）

- harness.ts pollCdpUrl 处理 403 与「Allow remote debugging?」提示：新版 Chrome 存在用户主动许可的远程调试流 [实证: 代码在库，移植期即有]
- readWsUrl 注释：Chrome 154+ Dev 对普通 --remote-debugging-port 启动不再写 DevToolsActivePort 文件 [实证: 代码注释在库；版本行为待外部核实]
- Chrome 136+ 对默认 profile 禁用 --remote-debugging-port [记忆: 安全变更传闻，待官方公告核实]

## 外部事实核查（2026-09-05）

- Q1 定案：Chrome 136 起 `--remote-debugging-port` 与 `--remote-debugging-pipe` 在默认 data directory 不再生效，必须伴随指向非标准目录的 `--user-data-dir`；动机为打击 infostealer 经 CDP 窃取 cookies；官方推荐自动化走 Chrome for Testing；Edge 136 同步受限 [实证: developer.chrome.com/blog/remote-debugging-port 官方原文取回，2025-03-17 发布]
- Q2 主通道定案：Chrome 144+ 官方 auto-connect 流与 D11 场景同构（连接用户个人浏览器、继承 tabs/扩展/登录态）：用户在运行中的 Chrome 打开 `chrome://inspect/#remote-debugging` 启用 remote debugging，工具侧自动发现并连接，Chrome 弹许可用户点 Allow [实证: developer.chrome.com/docs/devtools/agents/use-cases/auto-connect 官方文档取回，2026-05-13 更新]
- 发现机制（多源聚合，待 PoC 证实）：启用后 CDP server 绑 127.0.0.1 随机端口、无需重启；DevToolsActivePort 文件写入 user data dir；chrome-devtools-mcp 的 --autoConnect、agent-browser、Playwright attach 均按此发现 [推断: 端口与文件机制官方文档未细述，来自 agent-browser 文档与社区多源，PoC 定案]
- 通道格局结论：flag 通道（默认 profile）已死、许可通道为官方正版。D11 的「用户自开为主」在 Chrome 144+ 上有官方支持路径 [实证: 上述两官方信源交叉]

## 本机探测（2026-09-05）

- 首轮探测误判「Chrome 未装」：只查了 stable 安装路径，被用户纠偏；实际装的是 Chrome Dev 155.0.8040.2（`C:/Program Files/Google/Chrome Dev/Application/chrome.exe`），默认 profile 在 `%LOCALAPPDATA%/Google/Chrome Dev/User Data` [实证: 纠偏后 PowerShell 复测]
- 注册表 StartMenuInternet 自适应发现可见：Brave、Google Chrome Dev、IEXPLORE、Microsoft Edge；用户指令排除 Edge，发现面向 Chrome 家族 [实证: 注册表扫描 + 用户指令 2026-09-05]
- Chrome Dev profile 的 DevToolsActivePort 在 toggle 启用前不存在、启用后即时出现（见 PoC 节）[实证]

## PoC 实测（2026-09-05，poc/S001-附着通道/attach-poc.mjs）

- 环境：本机 Chrome Dev 155.0.8040.2（默认 profile `%LOCALAPPDATA%/Google/Chrome Dev/User Data`），用户日常实例运行中（15 进程）[实证]
- 用户启用 toggle：`chrome://inspect/#remote-debugging` 开「Allow remote debugging for this browser instance」，页面明示 Server running at: 127.0.0.1:9222（固定端口 9222，非社区传闻的随机端口）[实证: 用户提供的 toggle 页文案]
- 发现：DevToolsActivePort 文件即时写入默认 profile，内容两行（端口 + /devtools/browser/<uuid> WS 路径）[实证]
- HTTP /json/version 返回 404：toggle 流不服务 /json HTTP 端点，WS 直连是唯一通道（与仓内 readWsUrl 注释一致）[实证]
- 附着：WS 直连 attempt 1 握手成功（首次尝试失败，用户点 Allow 许可后通过：per-connection 许可存在）[实证]
- 操作：Target.getTargets 列出用户真实 tabs（2 个）、Target.createTarget background:true 建专属 tab、Target.closeTarget 清理，全部成功 [实证]
- 生死门判定：**可行**。用户自开浏览器（默认 profile、Chrome 144+）可被发现、附着、操作 [实证: 上述完整链路]

## 待补观察项（已定案）

- 建后台 tab 是否抢用户焦点：**不抢**（用户肉眼确认，两 tab 共存场景实测）[实证: 2026-09-05]
- 许可弹窗：**每次新 WS 连接都弹 Allow**（用户确认第二次连接再次弹窗）[实证: 2026-09-05]
- toggle 重启持久性：未验证（非阻塞遗留，架构不依赖它；下次浏览器重启后顺手回填）

## 结论

**判定：可行。D11 生死门通过。**

用户自开浏览器（Chrome 144+、默认 profile、toggle 启用）可被发现、附着、操作，专属 tab 后台创建不抢用户焦点。证据链：官方通道存在（auto-connect）+ 本机全链路 PoC 五步通过 + 共存观察确认。

### discovery 模块设计输入

| 维度 | 规格 | 依据 |
| --- | --- | --- |
| 发现源 | 默认 profile 的 DevToolsActivePort 文件（两行：端口 + WS 路径） | [实证: PoC] |
| 浏览器自适应 | 注册表 StartMenuInternet 扫描定位 Chrome 家族与 user data dir（本机为 Chrome Dev 155）；Edge 明确排除（用户指令 2026-09-05，亦合 M006 教训） | [实证: 注册表扫描 + 用户指令] |
| 连接方式 | WS 直连 DevToolsActivePort 的 browser 级端点；HTTP /json 系端点不服务（404），不可依赖 | [实证: PoC] |
| 许可模型 | 每条新 WS 连接弹一次 Allow；daemon 必须持单条长连避免反复弹窗，重连时如实报「等待用户点 Allow」 | [实证: PoC 两次连接] |
| 引导形态 | 无需装快捷方式：空态引导 = 指导用户开 `chrome://inspect/#remote-debugging` 勾选一次；bh 检测 toggle 未开时如实报并给此指引 | [实证: 官方文档 + 用户实操] |
| 专属 tab | Target.createTarget background:true，不抢用户焦点；标记复用现有马标记机制 | [实证: PoC + 用户确认] |

### 遗留项（非阻塞）

- toggle 重启持久性：浏览器重启后是否保持启用，待观察回填
- Brave 等 Chromium 变体的 toggle 支持度：本机无日常使用场景，不展开
- 版本下限：Chrome 144+（官方口径）；本机 155 实测通过，低版本行为不保证
