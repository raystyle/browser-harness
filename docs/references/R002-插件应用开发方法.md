# R002：插件应用开发方法

> 现役方法手册：在 bh 上开发站点应用（搜索/抓取/监控类插件）的架构与合约。提炼自 nu_plugin_browse skills 生态（skills/browse、skills/twitter、skills/google、sdk 仓，2026-09-04 通读）。
> 现有插件 assets/apps/*.mjs 是 daemon 侧薄封装；本方法用于新应用与旧应用升级。

## 分层架构

```text
宿主层    bh daemon：CDP 通道、Session/Harness、agent Chrome 生命周期（src/session.ts, src/harness.ts）
SDK 层    页面侧常驻对象（window.__<app>）：TS 源码 -> iife minify -> 注入后常驻
          分层参考：core(done/log/context) + dom(query/wait) + http(interceptor) + schema + services/<site>
命令层    assets/apps/<app>.mjs：薄封装——ensure 会话 -> 调 SDK 方法 -> check 合约 -> stash/pluck
Agent 面  skill/SKILL.md 与 domain-skills：命令表 + 错误决策树 + 版本合约
```

核心原则：**站点逻辑住进页面（常驻 SDK），命令层只是一次 `__<app>.method()` 调用的薄壳**。不逐次 evaluate 手写内联 JS。

## 固定形合约（每个 SDK 方法）

```js
{ _ok: boolean, _v: '<合约版本>', _ts: '<ISO>', ...固定字段 }
// 失败： { _ok: false, error: '<分类前缀>: <detail>' } —— 永不返回 null/undefined
```

- `_ok: false + error` 替代 null 语义：「网络失败」与「服务端返回空」永不混淆
- 命令层统一 check：验 `_ok/_v/_ts` 存在（guard）+ `_ok` 判定（check），失败转用户友好消息
- **版本合约**：SDK 侧 `CONTRACT_VERSION` 与命令层常量必须相等，改返回形状必须 bump

## 两步契约（集合数据防截断/冻结）

1. 第一步（抓取）：数据落盘 `<workspace>/cache/<cache>.json`（batch 追加、留最近 100、tmp+rename 原子写）；只返指标：

```js
{ _ok: true, count: 38, shape: { item: ['id','text','favs'], item_types: {id:'string',favs:'int'} },
  bytes: 24710, cache: 'tw_home', batch_id, total_batches }
// 恒 <1KB；shape 让 agent 不取数就知道怎么 select/where
```

2. 第二步（取数）：`<app> pluck <cache>` 读最新 batch，进管道分析（过滤/聚合/分页合并）

适用：搜索结果、时间线、列表成员、批量正文。小返回（单条 profile、状态查询）直接返回不走两步。

## 会话生命周期

```text
ensure: status=open 且 SDK 探活(__<app>.ready() 带超时) -> 复用；探活失败 -> 强制重开
open:   注入 SDK -> 导航 -> 探活验证通过才报成功（注入成功 != 可用）
close:  关停会话
```

## 纪律

- **单命令 per evaluate**：一次 evaluate 内多个命令会冻结浏览器（CDP 阻塞在并发请求）
- **CAPTCHA/墙：停止不重试**，提示用户在窗口手动验证后继续（墙是状态不是空结果，与 detect_page_blocks 哲学一致）
- **错误分类前缀**：AUTHORIZATION（不可恢复）/ RATE_LIMITED（等 reset）/ LOCKED（人工）/ NOT_FOUND / NETWORK / TIMEOUT；决策树进 SKILL.md
- **过热重置**：请求计数达阈值置 `_cool_reset`，close+open 重置
- **参数序列化一次**：拼调用表达式时 to-json 恰好一次，双重序列化是经典事故
- **正文提取走 HTTP 侧车**：纯抓正文不经浏览器（bh 的 web-fetch 已是此模式）；浏览器只做需要交互/登录态的事

## 开发流程（新应用）

1. SDK：TS 源（可暂用单文件）-> `ready()`（就绪判官：等关键 DOM/接口）+ 业务方法（固定形合约）
2. 编译成 iife min.js 放 assets/apps/（构建命令记此处，产物进 git）
3. 命令层 .mjs：ensure（注入+探活）-> 方法调用 -> check -> stash/pluck
4. SKILL 面登记：命令表、两步契约 cache 名、错误决策树、版本合约
5. 验收：墙场景如实报告、大结果不 inline、断连自动重开会话

## 升级现有插件的判据

内联 JS 探针出现以下信号时升级为 SDK 常驻：探针偶发空结果（无就绪判官，如 bing title 空 M004 同源）、返回数据可能超 ~10KB、需要跨调用状态（cursor/计数/日志）。
