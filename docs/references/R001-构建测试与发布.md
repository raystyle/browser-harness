# R001：构建、测试与发布流程

> 现役操作手册：从源码到发布与诊断的日常流程。命令在 Windows(pwsh) / Linux / macOS 通用（npm 脚本）。

## 前置

- Node >= 22（本机实证 24.20）；无需全局工具，`npm install` 后即可开发

## 构建

```powershell
npm run build     # tsc -> dist/
npm run dev       # watch 模式
```

## 测试

```powershell
npm test          # build + node --test "dist/*.test.js"
```

注意（Windows git-bash）：glob 必须带引号，否则目录参数解析出错（见 M002）。

## 开发 vs 安装验收（两套家，禁止混用）

判定：`src/paths.ts` 看包根有没有 `tsconfig.json`（npm 包不含此文件）。有 = 开发态，没有 = 安装态。

| | 开发 | 安装验收 |
| --- | --- | --- |
| 入口 | 仓库里 `npm run build` 后 `node dist/cli.js`，或 `npm link` | `npm pack` 再 `npm install -g ./browser-harness-ts-*.tgz`，然后 PATH 上的 `bh` |
| BH_HOME | `<repo>/.bh-dev` | `~/.config/browser-harness` |
| 用途 | 单测、改源码、不碰用户登录态与收割库 | 真 Chrome、看板、常驻应用、技能分发 |
| 看板 | `node dist/cli.js dashboard`（读 .bh-dev） | `bh dashboard`（读用户目录） |

禁止：从仓库直接起 `node dist/dashboard.js` 去看安装态正在跑的 page-detect / supervisor。两边 data 目录不同，监控台会一直空或不刷新。[实证: 2026-09-07 看板读 .bh-dev、应用写 ~/.config] 踩坑条目 M014。

安装验收步骤（改完源码要给人看时走这条，不要 `npm install -g .` / 不要 `npm link`）：

```powershell
npm test
npm pack
npm install -g ./browser-harness-ts-*.tgz
Remove-Item ./browser-harness-ts-*.tgz
bh --version
bh skill sync --yes
bh dashboard stop; bh dashboard start
bh doctor
# 打开 http://127.0.0.1:9870
```

开发日常：

```powershell
npm run build          # 或 npm run dev
npm test
node dist/cli.js …     # 或 npm link 后的 bh；数据在 .bh-dev
```

`BH_HOME` 环境变量可钉死家目录；未钉死则不要跨态共用 daemon / 看板 / rmux 会话。

## 代码生成（协议升级）

- `src/generated.ts` 由 `scripts/gen.ts` 从 `protocol/browser_protocol.json` + `protocol/js_protocol.json` 生成，禁止手改
- 协议换版流程：替换 `protocol/*.json` -> `npm run gen` -> `npm test` -> 冒烟一个新方法调用
- 保真判据：与上游 browser-harness-js 生成物 diff，仅允许头两行注释差异 [实证: 2026-09-04 首次生成对账]

## 发布（封版）

不走 npm registry 发布（2026-09-07 裁定）：本地 `npm pack` + 全局 tgz 安装分发（GitHub Release 附 tgz）。

封版八步（顺序执行，缺一不可）：

1. 版本号：`package.json` 与 `package-lock.json`（两处 version）同步提版
2. CHANGELOG 封版：`[Unreleased]` 转版本号 + 日期；README 安装示例与 `bh --version` 输出同步
3. `npm test` 全绿
4. **本地升级验收（2026-09-08 用户固化）**：`npm pack` -> `npm install -g ./browser-harness-ts-*.tgz` -> `bh --version` 对版 -> 安装态冒烟（`bh --status` / `bh skill sync --yes` / 任一插件路由 / `echo 'return 1+1' | bh`）
5. **守护面滚动**（0.4.1 起一条命令）：`bh upgrade --yes`（默认 dry-run 打印计划；自动查 GitHub Release，不高于本地不降级，离线降级为滚动本地；`--from <tgz|URL>` 显式源连安装一起做）。手动等价序列：`bh x-intel stop` -> 杀 page-detect watch 与 supervisor-core 会话 -> `bh --restart --yes`（default daemon 重生 + companions 重拉）-> `bh dashboard stop` && `bh dashboard` -> `bh x-intel start`；以 `/health` 自报 `version` 字段、`bh sessions` 三 daemon `cdp:true`、看板 200 终验
6. git 提交（feat:/fix:/chore: 一事一提交）+ `git tag -a v<版本>`
7. diary 记钩子
8. ROADMAP 阶段状态（如有里程碑变化）

## 技能分发

```powershell
bh skill status    # 三线对账：repo payload <-> npm 包 <-> 已部署副本
bh skill sync --yes # 同步（三线哈希防漂移、只增不删；无 --yes 时仅打印计划）
```

## 诊断

```powershell
bh doctor --json    # 环境体检（机器可读，含「browser attachable」检查）
bh --stop           # 关停 daemon（只关 daemon 自身连接，不动用户浏览器）
```

- 附着模型（D11 起）：bh 永不 spawn 浏览器；无可附着浏览器时按 doctor/报错指引开 `chrome://inspect/#remote-debugging` 的「Allow remote debugging for this browser instance」
- daemon 日志默认 `%TEMP%/bh.log`（`CDP_REPL_LOG` 覆盖）；server 以分离进程拉起，不随终端退出
- WebSocket 连接失败、端口冲突、tab 输入挂起等已知陷阱查 M101
